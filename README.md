# Интеграция с FastAPI

## Описание

В данной контрольной точке вам предстоит реализовать интеграцию с **API сервиса заявок**. 

Создайте ветку со своей фамилией и работайте в ней. 

```sh
git switch -c <фамилия-измени-меня>
```

## Требования и критерии оценивания

**Весь функционал, за который вы планируете получить хотя бы 1 балл, должен работать без изменений с моей стороны**

### Общие требования
- токен доступа хранится в контексте, персистентность настроена через `localStorage`;
- на страницах проверяется наличие токена, запрашиваются данные о пользователе с бэкенда, при наличии данные передаются в компоненты;
- отображаются спиннеры обработки, а так же ошибки клиента и сервера;
- на страницах, требующих авторизации, присутствует информация о пользователе и предусмотрена возможность логаута;
- желательно также отображать сообщения об успешных действиях;

### Функционал регистрации

- страница доступна по `/register` либо `/signup`;
- в случае успешной регистрации происходит перенаправление на `/login`;
- закрыт доступ для залогиненных пользователей; 
- присутствует ссылка для перехода на логин;

### Функционал логина

- страница доступна по `/login`;
- отображаются ошибки валидации формы + ошибки, приходящие с бэкенда;
- в случае успешного логина происходит сохранение токена в контекст и `localStorage`;
- после сохранения токена происходит перенаправление на `/`;
- закрыт доступ для залогиненных пользователей; 
- присутствует ссылка для перехода на регистрацию;

### Функционал посадочной страницы

- страница доступна по `/`;
- страница проверяет наличие токена: если пользователь залогинен, происходит перенаправление на страницу `/records`;
- когда страницу посещает гость, ему отображается краткая информация о курсах и количестве заявок по каждому из них, а также блок действия с ссылкой на вход/регистрацию;

### Функционал списка заявок

- страница доступна по `/records`;
- отображается список заявок пользователя (фильтрация по курсу и пагинация не требуются);
- пользователь может удалить заявку;

### Дополнительные (бонусные) требования

- типизировать `allRecordsFn` (1 балл);
- реализовать функции для регистрации, создания заявок и удаления заявок по аналогии с имеющимися в `api/client` (1 балл);
- перевести хотя бы одну страницу на кастомный хук `useQuery` (1 балл);
- перевести хотя бы одну страницу на кастомный хук `useMutation` (1 балл);
- проследить, чтобы гости не получили подробную информацию о всех заявках (в том числе через инструменты разработчика), возможно, потребует правок бэка (1 балл);
- перед удалением запрашивать подтверждение (1 балл);
- типизировать по умному параметры фетчера (например, при методе `post` и контент-тайпе `x-www-form-urlencoded` ожидать `body` в виде `URLSearchParams`, при методе `post` и контент-тайпе `json` ожидать `body` в виде объекта, а при методе `get` тело должно отсутствовать). (1 балл)

### Функционал создания заявки

- страница доступна по `/records/create`;
- после успешного создания заявки происходит перенаправление на страницу всех заявок;

## Настройка и запуск

Бэкенд и фронтенд размещены в псевдо-полиглот-репозитории. Если вы пользуетесь `macOS` либо иными `*nix`-системами, предварительно замените команды для активации `venv`-окружения в `backend/package.json`.

При запуске `npm i` будут установлены зависимости как на фронте, так и на бэке. 

### Бэкенд

Настройте **переменные окружения**: путь к файловой базе данных и секреты/соли для хеширования и шифрования.

```powershell
# windows

copy .env.example .env
```

```sh
# unix

cp .env.example .env
```

Инициализируйте БД и наполните её данными

```sh
# windows / unix
npm run db:seed
```

Запустите бэкенд

```sh
# windows / unix
npm run dev:backend
```

Добро пожаловать в документацию по ссылке <http://localhost:8000/docs>!

### Фронтенд

Фронтенд не требует особой настройки и запускается классически

```sh
# windows / unix
npm run dev:frontend
```
